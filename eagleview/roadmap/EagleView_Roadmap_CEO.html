Phase 4 · Security & Compliance
Every CEO Must Know This Before Saying Yes
Address data, privacy, and security concerns before IT or legal raises them
0 / 7
▼
Data Privacy
Confirm: Eagle View does NOT send any email content to external servers
Data flows directly: Microsoft / Google → Eagle View on the employee's desktop — no third-party cloud involved
TECH
Confirm: only metadata is used (mail count, sender name, meeting time) — not email body content
Eagle View reads: unread count, sender, subject, time. It never reads, stores, or transmits email body text
TECH
Confirm: all tokens stored locally and encrypted by the OS keychain
Auth tokens are stored in the OS-level secure storage — not in plain text files or a shared database
TECH
Confirm GDPR compliance position: local processing, no personal data leaves the device
Because Eagle View is local-first with no backend server, GDPR compliance is substantially simpler than cloud SaaS
LEGAL
IT Approval
Share the API permission list with IT: User.Read, Mail.Read, Calendars.Read — read-only
These are the minimum necessary permissions — no write access, no admin access, no user impersonation
TECH
Confirm IT can revoke Eagle View access at any time via Azure AD without touching employee machines
IT admin can delete the app registration in Azure AD and all employees are instantly signed out — full control retained
TECH
Get written IT sign-off before the company-wide rollout decision
A CEO decision without IT sign-off causes painful reversals later — get IT onboard at this stage, not after

TECH

TECH

Deploy the installer to all machines on the announced go-live date
IT pushes to all machines in one batch — Eagle View appears in the Applications folder without user action
TECH
